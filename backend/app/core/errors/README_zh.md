# 错误码规范

## 格式
错误码格式：`[模块字母][分类编号][序列号]`
示例：`A01XX`
- `模块字母`：模块标识（1个字符）
- `分类编号`：错误分类（2位数字）
- `序列号`：错误序号（2位数字）

## 模块前缀（字母）
- `A`：通用错误（系统通用错误）
- `B`：账户相关（用户、租户、认证）
- `C`：模型提供者相关（AI模型、供应商）
- `D`：应用相关（应用管理）
- `E`：工作流相关（工作流执行）

## 分类编号（2位数字）
- `00`：系统级别（系统错误、内部错误）
- `01`：认证和授权
- `02`：输入参数验证
- `03`：资源相关（未找到、已存在）
- `04`：操作相关（创建、更新、删除）
- `05`：限流和配额
- `06`：外部服务/集成
- `07`：数据处理和验证
- `08`：配置相关
- `09`：安全相关
- `10`：业务逻辑相关

## 实现示例
```python
class CommonErrorCode(BaseErrorCode):
    """
    通用错误（分类 A）
    
    分类说明：
    00: 系统级错误
    01: 认证和授权
    02: 输入参数验证
    03: 资源相关
    04: 操作相关
    05: 限流和配额
    """
    # 系统级错误 (00)
    INTERNAL_SERVER_ERROR = ("A0001", "系统内部错误")
    SERVICE_UNAVAILABLE = ("A0002", "服务暂时不可用")
    
    # 认证和授权 (01)
    UNAUTHORIZED = ("A0101", "未经授权")
    PERMISSION_DENIED = ("A0102", "权限不足")
    TOKEN_EXPIRED = ("A0103", "令牌已过期")
    
    # 输入参数验证 (02)
    INVALID_ARGUMENT = ("A0201", "无效的参数")
    INVALID_FORMAT = ("A0202", "无效的数据格式")
    MISSING_REQUIRED_FIELD = ("A0203", "缺少必填字段")
    
    # 资源相关 (03)
    RESOURCE_NOT_FOUND = ("A0301", "资源未找到")
    RESOURCE_ALREADY_EXISTS = ("A0302", "资源已存在")
    
    # 限流相关 (05)
    RATE_LIMIT_EXCEEDED = ("A0501", "请求过于频繁")
    QUOTA_EXCEEDED = ("A0502", "超出配额限制")
```

## 使用指南
1. **一致性**：在所有模块中使用一致的命名和分类方式
2. **清晰性**：错误信息应清晰且具有描述性
3. **文档化**：始终包含分类注释和描述
4. **可扩展性**：在每个分类中预留足够的错误码空间
5. **唯一性**：确保错误码在所有模块中唯一

## 最佳实践
1. 保持错误信息友好且可操作
2. 使用适当的HTTP状态码配合错误响应
3. 包含相关错误详情，但不暴露敏感信息
4. 考虑国际化需求
5. 在API文档中记录所有错误码

## 错误码结构
- 第一个字符（字母）：标识模块
- 接下来两位（分类）：标识模块内的分类
- 最后两位（序号）：分类内的序号

## 注意事项
- 生产环境中的错误码应保持不变
- 废弃的错误码不应重复使用
- 更新错误码时需考虑向后兼容性
- 定期检查和清理未使用的错误码
